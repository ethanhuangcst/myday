# MyDay Web App
- A daily planning web app integrating capabilities such as ChatGPT LLM (Chat & Image Generation), Google Maps, TripAdvisor, Weather, and Zodiac insights
- That helps users start their day with personalized recommendations.

## Overview
- Entry screen that allows users to enter their personal information and save it as their profile
- Provide zodiac insights
- Based on the user's profile, weather, today's mood, and zodiac insights, recommend today's outfit
- List nearby restaurants based on the user's location (auto-detected; manual entry if unavailable)
- Highlight TripAdvisor reviews for the restaurants if any

## Requirement
### Profile List
- A **card grid** to display all existing profiles (interaction cards)
- Each profile displays as a card, with name and photo
- Click a profile card to enter "Plan my day"
- Click "Create a new profile" button to enter "Create a new profile"

### Create a new profile
- User enters personal details
  - Name
  - Gender
  - Date of birth
  - Upload a photo of yourself (**required**)
  - Height
  - Weight
  - Occupation
- Photo is mandatory: **Save** stays disabled (or shows a visible validation message) until a photo is uploaded; do not persist a profile without a photo
- Clicks "Save" button; the profile will be saved

### Plan my day
- **My profile** and **What am I into?** as separate full-width section cards (layout: **UI guidelines — section-card stack**)
- "My profile" section: allow the user to view/edit the profile information, with a "Delete" function (confirmation required); photo remains **required** on edit (same validation as create)
- "What am I into?" section:
  - Get the current location (default: browser geolocation; manual entry if unavailable)
  - User manually enters "My mood now", e.g., "excited"
  - User manually enters "What I'm doing today", e.g., "travelling"
- Click "Plan my day" button to enter "My day plan"

### My day plan

Layout: **UI guidelines — section-card stack**. Content by section:

- **Header** section card
  - "Hello, {name}" + profile photo
  - Display personal information with auto-calculated age and zodiac sign
- **Weather** section card: query weather for the current location
- **Zodiac insights** section card
  - Fetch natal chart + current transits from Pandorium MCP using the required `birthData` shape (see `2.tech-spec.md`)
  - Based on "What am I into" inputs and that astro context, use LLM for personalized recommendations
  - Render insights as an **inner 2×2 card grid** (4 cards) inside this section — not a single prose block:
    1. **Overall** — short vibe / chart summary for today
    2. **Things to do** — actionable suggestions
    3. **Things to avoid** — gentle cautions
    4. **Playful tips** — one or more fun tips
  - Each of the four cards has its own heading (i18n) and body; stack to one column on narrow mobile if needed, 2 columns from `sm` up
  - Surface MCP or LLM failures in this section — never a blank ready state
  - API returns structured fields (`overall`, `thingsToDo`, `thingsToAvoid`, `playfulTips`); do not rely on free-form markdown alone for layout
- **Outfit recommendation** section card
  - Based on weather, "My mood now", "What I'm doing today", and zodiac insights, use LLM to generate outfit recommendation (display as text)
  - Use image LLM to generate a portrait with today's outfit recommendation
    - Use **image edit** with the required profile photo as the reference image to generate a highly realistic avatar in today's outfit
    - The generated portrait must match the outfit recommendation text from the LLM
  - Ensure the image is properly displayed with the visibility of the whole body (portrait aspect)
  - Use only **API-supported** image sizes/quality (see `2.tech-spec.md`: portrait `1024x1536`, `quality: low`); never invent sizes such as `512x768`
  - Target completion within **20 seconds**; if still working after ~10s, show “more time is needed” (never the word “Timeout”)
  - If image generation fails, show a clear per-section error + retry; text outfit can still display — **never fail silently**
- **What to eat today** section card
  - Let the user choose a cuisine (Japanese, Spanish, Italian, fast food, Cantonese, etc.)
  - Call the map API to find suitable restaurants within 3 km of the current location
  - Display results as a **true vertical list** (not a card grid): one row per restaurant, sorted by distance, scannable on mobile and desktop
  - **Each list row must include:**
    - **Front image** (leading thumbnail): Google Places photo when available; otherwise TripAdvisor photo when listed; otherwise a neutral placeholder (never a broken image)
    - **Primary text:** restaurant name + distance
    - **Secondary text:** address; rating / review count when available
    - **Review snippet:** brief string summary — prefer TripAdvisor review text when the place is listed; otherwise a Google Places review excerpt when available. Localized Terra fields must be flattened to plain text before render
    - **TripAdvisor indicator** when the place is listed on TripAdvisor
  - On restaurant row click, open a floating popup for restaurant detailed information, with an embedded map showing the restaurant location with navigation, and close / Escape / backdrop
  - Serve Google Place photos through a **server photo proxy** (do not expose the Maps key in client `img` URLs)

### Performance and user friendly
- Always show user tips and progress **per section** when that section is generating
- Do not wait until all sections are ready — reveal each section card when its content is ready
- **Latency (single rule across all docs):**
  - Soft tip: after ~**10 seconds**, show “more time is needed” while work continues
  - Target: each section’s content ready within **20 seconds**
  - Do not document or implement a separate conflicting 10s hard timeout that abandons the section early without a user-visible state

## UI guidelines
Tone: **clean, neat, fun** — a light morning desk for planning the day, not a dense dashboard or marketing landing page.

### Visual direction
- **Palette (CSS variables):** Paper `#F7F9FC` · Mist `#E8F1F8` · Ink `#1B2430` · Soft slate `#5B6B7C` · Sun `#F4A261` (primary CTA / progress accent) · Fresh `#2BB673` (success only)
- **Surfaces:** soft sky-to-paper wash or subtle grain; avoid flat single-color pages and heavy purple / neon / dark-mode defaults
- **Type:** distinctive display for greetings / section titles (e.g. Outfit or similar geometric friendly face); clear sans for body and forms — never Inter, Roboto, Arial, or system UI stacks as the brand voice
- **Layout — section-card stack (required look & feel):**
  - Render as a **vertical stack of section cards** — **one content kind per card**
  - Do **not** merge section content into one flat column; do **not** use a multi-column dashboard grid that mixes weather / zodiac / outfit / food side by side
  - Content screens use a **single-column vertical stack** of full-width **section cards** (Plan my day, My day plan, create/edit profile form sections, and the same language elsewhere)
  - Each card is visually distinct (border + light tint / accent per kind: e.g. sky for weather, star for zodiac, sun for outfit, leaf for food) so the page reads as a structured card layout, not one undifferentiated text wall
  - Each section card has: distinctive accent/surface, own heading (i18n), body, and its own loading / empty / error state
  - First screen (profile list): calm composition — brand + short prompt + profile **card grid** + primary create action — not a section-card stack for the grid itself
- **Interaction cards:** profile pick only — name + photo grid
- **Restaurant list (food section):** vertical list rows with leading front image + text column (name, distance, address, rating, review snippet). Do not render restaurants as a multi-column card grid
- **Motion:** 2–3 intentional moments (section fade-in as content arrives, button press, dialog open/close); respect `prefers-reduced-motion`
- **Signature:** the progressive “day assembling” reveal — each stacked section card loads and appears on its own with light progress tips, not a single loading spinner for the whole page

### Page sections

Composition per screen (each section follows **section-card stack** above unless noted):

| Screen | Sections (top → bottom) |
| --- | --- |
| Profile list | Header · Profile card grid · Create profile action |
| Create / edit profile | Header · Profile form section card · Save action |
| Plan my day | Header · My profile section card · What am I into? section card · Plan my day action |
| My day plan | Header · Weather · Zodiac insights · Outfit recommendation · What to eat today — each a full-width stacked section card with its own tone |

### Interaction & copy
- Primary actions use plain verbs that match outcomes (e.g. Save → saved confirmation; Plan my day → day plan)
- Form validation and error messages are correct and visible (including required profile photo on create and edit)
- Empty, loading, and error states explain what to do next; never show raw “Timeout” — say more time is needed; never hide image/API/MCP failures without a section message
- All user-facing strings are **i18n keys** (default locale + at least one additional locale path); no hard-coded UI copy
- Keyboard: visible focus, Escape / backdrop closes dialogs; status is not color-only
- Desktop and mobile: no clipped controls; restaurant list rows stay full-width and scannable (image + text), never a restaurant card grid
