## UX performance

**Latency (one contract only — matches `1.requirement.md`):**

- Soft tip: after ~**10s**, show “more time is needed” while work continues (never the word “Timeout”)
- Target: each section ready within **≤20s**
- Do **not** implement a separate conflicting 10s hard timeout that abandons the section early without a user-visible state

Fetch sections in parallel; stream / render each piece as it completes (per-section tips + progress while pending). Local fortune fallback only if chat fails or the section remains empty after the user-visible wait path — not as a silent swap at 10s.

## Implementation pitfalls (must follow)

Cross-check when implementing; these are the traps that diverge from `1.requirement.md`:

| Area | Contract |
| --- | --- |
| **UI** | Vertical **section-card stack** (distinct tones per kind). Profile list = **card grid**. Restaurants = **list rows** (front image + review snippet) — never a restaurant card grid or day-plan multi-column dashboard |
| **Latency** | Soft tip ~10s · target ready ≤20s — **one contract only** (see UX performance) |
| **Chat** | Use `max_completion_tokens` — **not** `max_tokens` (gpt-5.x / current OpenAI chat params) |
| **Image** | Size `1024x1536`, `quality: low` only; never invent sizes (e.g. `512x768`). Never silent image failure — per-section error + retry; text outfit may still show |
| **Zodiac** | Pandorium tools need `birthData` + timezone; surface MCP/LLM errors **in-section** (never blank ready) |
| **Restaurants** | Google photo proxy `/api/places/photo` (no Maps key in client `img` URLs); Terra reviews/photos for enrichment; **flatten** localized Terra/Google strings to plain text before render |

Copy keys into `.env.local` (gitignored; do not commit). Do not hardcode in source.

**Environment — Google Maps key**

- **Do not** add `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` — use a single `GOOGLE_MAPS_API_KEY` (server Embed/config only; place photos via `/api/places/photo`).

```env

OPENAI_CHAT_MODEL=gpt-5.4

GOOGLE_MAPS_API_KEY=

TRIPADVISOR_BASE_URL=https://terra.tripadvisor.com/api
PANDORIUM_MCP_URL=https://pandorium.app/mcp
```

**ChatGPT (OpenAI)** — Host=`api.openai.com`

| Use | Value |
| --- | --- |
| Key | `OPENAI_API_KEY` (from `.env.local` only — never commit real values) |
| Base URL | `https://api.openai.com/v1` |
| Chat model | `gpt-5.4` |
| Image model | `gpt-image-1.5` |

- Chat: OpenAI `/chat/completions` via `openai` SDK (`gpt-5.4`) — fortune JSON / outfit text
  - Param: `max_completion_tokens` (**not** `max_tokens`)
- Image: OpenAI `/images` via `openai` SDK (`gpt-image-1.5`) — image edit with profile photo as reference for realistic avatar matching outfit text (profile photo required per `1.requirement.md`)
  - Params: `size: "1024x1536"`, `quality: "low"` (API-supported portrait only)
  - On failure: section error + retry — never silent empty image
- Latency: soft tip ~10s · target ≤20s (see UX performance); local fortune fallback if chat fails / empty after wait path

Smoke-tested:

| Call | Result |
| --- | --- |
| `GET /locations/nearby?lat=&lon=&radius=3&unit=KM` | OK · ~20 POIs / ~3s |
| `GET /locations/{id}` | OK · details |
