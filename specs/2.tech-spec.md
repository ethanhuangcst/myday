### OpenAI Image capability: gpt-image-1.5

- API Configuration
  - Model-name=`gpt-image-1.5`
  - Host=`api.openai.com`
  - API-Key=`OPENAI_API_KEY`
  - Base_URL=`https://api.openai.com/v1`
- Technical highlights
  - Endpoint: OpenAI `/images` via `openai` SDK (`gpt-image-1.5`) — image edit API
  - Params: `size: "1024x1536"`, `quality: "low"` (API-supported portrait only; never invent sizes)
  - **Performance tuning (≤20s section target; soft UI tip ~10s per** `1.requirement.md` **/ UX performance):**
    - Keep `quality: "low"` and `1024x1536` only — do not escalate quality or dimensions for “better” output; unsupported sizes fail or waste time
    - Request `n: 1`; no parallel duplicate image calls for the same outfit
    - **Downscale the reference profile photo on the server** before edit (e.g. cap long edge ~1024px, sensible JPEG/WebP) to cut upload latency and upstream processing
    - **Short, structured edit prompt** — outfit summary only; avoid repeating full zodiac/weather prose already shown in UI
    - **Do not serialise** outfit text LLM and image edit on the critical path when text is already available — return/display text first, run image edit immediately after (same section, two steps)
    - Server route: reuse a single `openai` client; set outbound **HTTP timeout ~25s** (buffer above 20s target) — do **not** implement a separate **10s hard abort** that drops the request while the UI still shows progress
    - On slow upstream: keep the request alive until timeout/error; surface “more time is needed” from the client after ~10s (per Performance) — never map a server cut-off to the word “Timeout”
    - Retry: **one** explicit user-triggered retry max per attempt path; do not auto-retry in a loop inside 20s
  - On failure: return error to caller for section error + retry — never silent empty image
  - Product behavior for profile photo / outfit avatar: see `1.requirement.md`

### Tripadvisor Terra capability: Terra API

## Performance

**Latency (all components — one contract only):**

- Soft tip: after ~**10s**, show “more time is needed” while work continues (never the word “Timeout”)
- Target: each component ready within **≤20s**
- Do **not** implement a separate conflicting 10s hard timeout that abandons the component early without a user-visible state

**Loading strategy (all components):**

- Fetch in **parallel** across independent components
- **Stream / render** each piece as it completes — do not block the whole view on the slowest component
- Show **per-component** tips and progress while work is pending

**Fallbacks:**

- Use **local fallbacks** only when upstream fails or the component is still empty after the user-visible wait path
- Do **not** silently swap to a fallback at ~10s while the UI still implies live generation



## Implementation pitfalls (must follow)

Cross-check when implementing; these are the traps that diverge from `1.requirement.md`:


| Area            | Contract                                                                                                                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **UI**          | Vertical **section-card stack** (distinct tones per kind). Profile list = **card grid**. Restaurants = **list rows** (front image + review snippet) — never a restaurant card grid or day-plan multi-column dashboard |
| **Latency**     | Soft tip ~10s · target ready ≤20s — **one contract only** (see Performance — all components)                                                                                                                          |
| **Chat**        | Use `max_completion_tokens` — **not** `max_tokens` (gpt-5.x / current OpenAI chat params)                                                                                                                             |
| **Image**       | Size `1024x1536`, `quality: low` only; never invent sizes (e.g. `512x768`). Never silent image failure — per-section error + retry; text outfit may still show                                                        |
| **Zodiac**      | Pandorium tools need `birthData` + timezone; surface MCP/LLM errors **in-section** (never blank ready)                                                                                                                |
| **Restaurants** | Google photo proxy `/api/places/photo` (no Maps key in client `img` URLs); Terra reviews/photos for enrichment; **flatten** localized Terra/Google strings to plain text before render                                |
