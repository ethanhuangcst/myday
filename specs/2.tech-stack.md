Rules: no DB; chat and image via `openai` SDK against OpenAI API; maps / Places / Directions / Embed via Google; weather via Open-Meteo; fortune via Pandorium; TripAdvisor for review enrichment; minimal deps. Keep secrets in `.env.local` only (never commit).

## UX performance

- Target: each section ready within **10s** (per `1.requirement.md`)
- Fetch sections in parallel; stream / render each piece as it completes (tips + progress while pending)
- Timeouts: chat / fortune ≤10s (local zodiac fallback if LLM slow); outfit text ≤10s; outfit image ≤10s with placeholder until ready; weather / restaurants ≤10s

## APIs

Put keys only in `.env.local` (see `3.initialization.md`). Do not hardcode in source or commit secrets.

**ChatGPT (OpenAI)** — Host=`api.openai.com`

| Use | Value |
| --- | --- |
| Key | `OPENAI_API_KEY` (from `.env.local`) |
| Base URL | `https://api.openai.com/v1` |
| Chat model | `gpt-5.4` |
| Image model | `gpt-image-1.5` |

- Chat: OpenAI `/chat/completions` via `openai` SDK (`gpt-5.4`) — fortune JSON / outfit text
- Image: OpenAI `/images` via `openai` SDK (`gpt-image-1.5`) — No photo → text-to-image; with profile photo → image edit (reference) for realistic avatar matching outfit text
- Enforce 10s section budgets; local fortune fallback if chat times out

**Google Maps** — `GOOGLE_MAPS_API_KEY` / `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` · Places · Directions · Maps JS / Embed

Smoke-tested (Shanghai `31.2304,121.4737`):

| API | Result |
| --- | --- |
| Places Nearby (legacy) | OK · ~20 restaurants / 3 km |
| Places API (New) `places:searchNearby` | OK · restaurant results |
| Directions | OK |
| Geocoding (reverse / forward) | OK · e.g. `31.2304,121.4737` → 人民广场；`Shanghai Bund` → 外滩 |
| Time Zone | OK · `Asia/Shanghai` |
| Maps JavaScript | OK |

**Open-Meteo** — `https://api.open-meteo.com/v1/forecast` · no auth · temp / weather code / humidity / wind

Smoke-tested: OK (~1.2s) · `current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m`

**Tripadvisor** — `https://terra.tripadvisor.com/api` · `TRIPADVISOR_API_KEY` · header `X-API-Key`

Smoke-tested:

| Call | Result |
| --- | --- |
| `GET /locations/nearby?lat=&lon=&radius=3&unit=KM` | OK · ~20 POIs / ~3s |
| `GET /locations/{id}` | OK · details |
| `GET /locations/{id}/reviews` | OK HTTP · may return empty `data` for some locations |
| Content API `api.content.tripadvisor.com` | denied with this key — use Terra host only |

Notes: use `lat` + `lon` (not `latLong`); `unit=KM` (uppercase). Cuisine filter for “What to Eat” should stay on Google Places; Terra is for review enrichment by location id/name match.

**Pandorium MCP** — `https://pandorium.app/mcp` · Streamable HTTP (JSON-RPC POST, SSE `data:` responses) · no auth · [docs](https://github.com/Naitellos/pandorium-mcp)

| `get_planet_positions` | OK · ~2.5s |
